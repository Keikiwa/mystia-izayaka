# 东方夜雀食堂：稀客 vs 普通客人 核心区别（复刻开发版）
> 出处：3DM游戏网《东方夜雀食堂》食堂经营攻略、日本wikiwiki《東方夜雀食堂》レア客（稀客）词条、九游稀客机制攻略

## 1. 刷新与解锁机制区别
1. **普通客人**：夜间营业默认从区域普通客人池随机刷新；营业开启即可出现，无前置剧情解锁条件，只受氛围控制刷新CD。
2. **稀客（レア客，东方角色）**
    - 必须**解锁对应区域, 开启主线/DLC剧情解锁**，才会加入当晚的客人候选池(可放到level_config调试)；未解锁完全不会刷新。
    - 刷新权重远低于普通客人，同氛围下出现概率更低；部分稀客需要“招待”前置操作才会来店。
    - 独立图鉴/绊（好感）系统：稀客拥有**绊等级**，普通客人无好感/图鉴记录；绊等级提升解锁该稀客的偏好Tag、配方奖励；绊最高Lv5，Lv5解锁全部喜好厌恶Tag。

## 2. 点单逻辑差异（最大业务分支，复刻重点）
- **普通客人**：直接点【成品料理+酒水】，仅自带喜好/厌恶Tag；没有**强制双要求限制**。评价仅计算料理+酒水所有Tag匹配分，评价等级S/A/B/C/D。
- **稀客**：点单阶段**强制提出2条硬性要求**：料理1个Tag要求、酒水1个Tag要求（两个独立约束）。
    1. 打分分为两层判定：①基础Tag分数（和普通客一样：喜欢Tag+1、讨厌Tag-1，加料Tag参与计算）；②**硬性双要求是否全部满足**，该条件锁评价上限。
    2. 锁上限规则：**双要求没有全部满足，无论基础Tag分多高，评价最高只能到橙评**；只有同时满足料理、酒水两条硬性要求，才可以解锁粉评（最高评价）。
    3. 例外：**夜雀厨具产出带夜雀之歌BUFF的料理，可以直接忽略稀客这两条硬性要求**，不再锁评价上限，仅按基础Tag分计算评价。
    4. 稀客自带独立【预算参数】，如果菜品总价超过稀客预算，直接判定黑评，触发惩罚符卡；普通客人无预算限制。
    5. 稀客有独立**流行风向态度参数**：部分稀客无视当日流行、部分特立独行，流行tag对其打分效果和普通客人不一样；普通客人统一受流行风向影响。(暂不实现)

## 3. 评价体系完全独立
- 普通客人：S/A/B/C/D 5档评价，仅影响收益、氛围、combo。
- 稀客：**独立5档评价：黑评、紫评、绿评、橙评、粉评**，不是SABCD。(但是可以用统一枚举+基础代码, 反正都是5档, 没必要各写一份代码, 只区分不同的地方)
    - 黑评：基础分≤0 或者菜品超预算 → 触发**惩罚符卡**，施加负面全局debuff，断Combo，降低绊等级、氛围。
    - 紫评：基础分=1，或者高分但双要求不满足 → 断combo，扣好感，无符卡。
    - 绿评：基础分=2，至少满足其中一项要求；小幅涨好感。
    - 橙评：基础分≥3，但**双要求没有全部达成**；中幅涨好感，不能触发奖励符卡。
    - 粉评（最高）：基础分≥4 + 料理&酒水双要求全部满足 → 触发**奖励符卡**，获得一次性全局经营buff，同时大量提升绊等级、氛围。

## 4. 结算奖励、符卡（Spell Card）机制（稀客独有）
普通客人：结算只产出金币，仅影响氛围、combo，**不存在符卡、绊奖励、配方/材料奖励**。
稀客：
1. 粉评触发**奖励符卡**：全局buff（例如持续生成小费、增加稀客刷新概率、提升店内氛围、其他特殊效果），符卡持续固定时长。
2. 黑评触发**惩罚符卡**：全局负面debuff（减慢上菜、降低客人耐心、降低氛围等）。
3. 绊等级奖励：每次结算会增减稀客的羁绊值；绊升级会解锁新菜谱、食材、店内功能、角色图鉴信息。
4. 部分稀客离场时会直接赠送食材作为额外奖励（独立于金币收益）。

## 5. 续单与基础状态参数差异
1. 耐心参数：稀客的**等待耐心衰减系数独立配置**，和普通客人不是同一套数值；部分稀客耐心掉的更快。
2. 续单：稀客拥有独立续单概率公式，除评价、氛围之外，额外叠加羁绊等级修正；普通客人使用一套统一续单公式。
3. 驱赶/跑单：稀客被驱赶或者耐心耗尽跑单，**除了扣氛围、清空combo之外，额外扣羁绊等级**；普通客人跑单仅扣氛围、重置combo，无好感扣除。

## 6. 其他次要差异
1. 对话事件：稀客落座、上菜、结算阶段会触发专属剧情对话；普通客人只有简单通用文本。
2. 图鉴记录：稀客信息存入米斯蒂娅手账图鉴；普通客人不记录到图鉴。
3. 部分稀客有特殊机制：例如部分稀客符卡可以召唤额外稀客进店，普通客人不存在这种连锁召唤逻辑。

## 补充：对原有数值公式的改动点（承接上一轮你拿到的经营公式）
普通客人评价：$S_{base}$直接映射S/A/B/C/D。
稀客评价：
1. 先计算基础分$S_{base}$（和普通客公式一致，料理+酒水+加料tag）；
2. 判定布尔变量 $Req_{full}$：料理硬性tag要求满足 AND 酒水硬性tag满足；
3. 结合$S_{base}$和$Req_{full}$映射【黑/紫/绿/橙/粉】五档；
4. 稀客的评价倍率、绊增减、符卡触发全部由这套新评价等级驱动，不再复用普通客人R_eval。
